# RLHF와 DPO: 사람이 더 좋아하는 답 쪽으로 모델을 민다

💬 AI › LLM · 2026-10-26 · 중급

> 💡 RLHF는 사람이 고른 선호 쌍으로 보상 모델을 학습한 뒤 강화학습으로 언어 모델을 최적화하고, DPO는 보상 모델 없이 선호 쌍에서 바로 언어 모델을 학습해 같은 목표를 더 간단히 이룬다.

## 선호 데이터

같은 질문에 대한 두 응답을 보여 주고 사람(또는 AI)이 더 나은 쪽을 고른다. '좋은 답'을 직접 쓰기보다 둘 중 나은 것을 고르는 편이 쉽고 일관적이다. 이 선호 쌍에는 정확성, 유용성, 안전성, 문체 같은 미묘한 기준이 담긴다.

## RLHF

(1) 선호 쌍으로 응답에 점수를 매기는 보상 모델을 학습한다(브래들리-테리 모델). (2) 언어 모델이 응답을 생성하면 보상 모델이 점수를 주고, PPO 같은 강화학습으로 점수를 높이도록 언어 모델을 갱신한다. 이때 원래 모델에서 너무 멀어지지 않도록 KL 벌점을 둔다. 보상 모델의 허점을 파고드는 '보상 해킹'이 주의할 점이다.

## DPO

DPO는 KL 제약이 있는 보상 최대화 문제의 최적해를 수식으로 풀어, 보상 모델과 강화학습 없이 선호 쌍에 대한 분류 손실 하나로 언어 모델을 직접 학습한다. 구현이 간단하고 안정적이어서 널리 쓰인다. 사람 대신 AI가 원칙에 따라 피드백을 주는 RLAIF·헌법적 AI 같은 방법도 있다.

## 🧮 핵심 수식·원리

```
보상 모델: P(y_w ≻ y_l) = σ(r(x, y_w) − r(x, y_l))
RLHF 목표: max E[r(x, y)] − β·KL(π_θ ‖ π_ref)
DPO: L = −log σ(β·[log π_θ(y_w|x)/π_ref(y_w|x) − log π_θ(y_l|x)/π_ref(y_l|x)])
```

## 🔍 예시·적용

연구 보조용 모델을 만들 때 '근거를 밝히고 불확실하면 그렇다고 말하는 답'을 선호하도록 선호 데이터를 모으면, 자신 없는 수치를 지어내는 경향을 줄이는 데 도움이 된다.

## ⚠️ 흔한 오해

RLHF가 모델을 '정직하게' 만든다고 단정하기 쉽지만, 실제로는 평가자가 선호하는 방향으로 민다. 평가자가 그럴듯한 오답을 좋아하면 그런 답이 강화될 수 있다(아첨 경향).

## 🔗 배터리 × AI

과학 분야에서는 전문가 선호 데이터가 비싸서, 도메인 전문가 몇 명의 비교 판단을 효율적으로 모으는 방법과 AI 피드백을 결합하는 방식이 연구된다.

## ❓ 퀴즈

DPO가 RLHF와 다른 가장 큰 점은?

- A. 선호 데이터를 쓰지 않는다
- B. 별도 보상 모델과 강화학습 없이 직접 학습한다
- C. 사전학습을 다시 한다
- D. KL 제약을 완전히 무시한다
